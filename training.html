Small-team AI enablement

Build real AI workflows, not canned demos.

A six-session, hands-on program for teams that want to understand and operate practical AI-assisted workflows. Each participant brings one real process from their work and develops it from a bounded workflow contract through tool connection, testing, recovery, and operator handoff.

Program outcome

By the final session, each participant should have a working bounded workflow or an evidence-backed prototype, a representative test set, and a short runbook describing how to operate, recover, and safely extend it.

Six-session structure

1. Make the workflow testable
Choose one useful process; define trigger, inputs, systems of record, allowed tools, output, approval boundary, acceptance tests, and recovery.
2. APIs, JSON & business data
Work with structured data, webhooks, files/CSV, authentication concepts, missing data, and predictable output schemas.
3. MCP & tool-connected agents
Connect one approved tool, inspect scopes, run read operations, preserve source traceability, and diagnose permission or missing-data failures.
4. Multi-step orchestration
Sequence steps, add branching, duplicate protection, schedules or event triggers, and explicit human approval before consequential writes.
5. Break it before production does
Test happy paths, missing sources, duplicates, denied permissions, partial failure, unknown write outcomes, and unsafe retry assumptions.
6. Operate & hand off
Run the final workflow, verify results, document ownership/scopes, create disable and recovery procedures, and define the next-step backlog.

How live sessions work

  • Short concept and demonstration block.
  • Guided build time on each participant's own process.
  • Group review of failures, edge cases, and trade-offs.
  • A concrete acceptance check and next-step assignment before the session ends.

For a cohort of roughly 6-7 participants, 90-120 minute sessions provide enough room for real implementation rather than slide-only instruction. Exact timing and tooling should be adapted to participant skill level and project complexity.

Topics the program can cover

Claude and other LLMs, AI agents, MCP, APIs, JSON, webhooks, structured outputs, file/spreadsheet workflows, n8n or comparable orchestration, approval gates, idempotency, bounded retries, verification, testing, and operator handoff.

What this is not

This is not a promise that every participant project can safely reach production in six sessions. Projects that need production credentials, custom API development, paid third-party services, data migration, security review, or substantial engineering are kept in prototype/read-only mode until those dependencies are separately scoped.
